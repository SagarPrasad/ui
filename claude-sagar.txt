  ---
  Document Summary

  Permission Model

  A 3-tier model built on Keycloak client roles with the naming convention
  temporal.<namespace>.<permission>:
  - Namespace access — workflow.read gates whether the namespace appears in the
  picker at all
  - Write gate — workflow.write (existing namespaceWriteDisabled check)
  - Action-level — 7 granular permissions: terminate, reset, signal, cancel,
  update, schedule, batch, plus activities

  Keycloak Steps

  1. Create a confidential OIDC client temporal-ui
  2. Create client roles following temporal.<ns>.<permission> convention (bulk
  creation script included)
  3. Optionally group them into composite roles (viewer, operator, developer)
  4. Assign roles to users or to groups
  5. Verify the token mapper includes resource_access.temporal-ui.roles in the
  JWT

  ---
  Running & Testing RBAC Locally

  There are three approaches, ordered by simplicity.

  ---
  Option 1 — Unit Tests (fastest, no servers needed)

  The parse-permissions.ts utility and buildCoreUser factory are pure functions
  — test them with Vitest directly.

  pnpm test -- --run src/lib/utilities/parse-permissions.test.ts

  Example test file to create at src/lib/utilities/parse-permissions.test.ts:

  import { describe, expect, it } from 'vitest';
  import { parsePermissionsFromToken } from './parse-permissions';

  const makeJwt = (roles: string[]) => {
    const payload = {
      resource_access: { 'temporal-ui': { roles } },
    };
    const b64 = btoa(JSON.stringify(payload));
    return `header.${b64}.signature`;
  };

  describe('parsePermissionsFromToken', () => {
    it('returns empty permissions for no token', () => {
      const result = parsePermissionsFromToken(undefined);
      expect(result.allowedNamespaces).toEqual([]);
    });

    it('grants namespace read access', () => {
      const token = makeJwt(['temporal.default.workflow.read']);
      const result = parsePermissionsFromToken(token);
      expect(result.allowedNamespaces).toContain('default');
      expect(result.namespaces['default'].read).toBe(true);
    });

    it('does not include namespace without workflow.read', () => {
      const token = makeJwt(['temporal.default.workflow.actions.signal']);
      const result = parsePermissionsFromToken(token);
      // namespace entry exists but is not in allowedNamespaces (no read perm)
      expect(result.allowedNamespaces).not.toContain('default');
    });

    it('parses action-level permissions', () => {
      const token = makeJwt([
        'temporal.payments.workflow.read',
        'temporal.payments.workflow.actions.terminate',
        'temporal.payments.workflow.actions.signal',
      ]);
      const perms = parsePermissionsFromToken(token).namespaces['payments'];
      expect(perms.actions.terminate).toBe(true);
      expect(perms.actions.signal).toBe(true);
      expect(perms.actions.reset).toBe(false);
    });

    it('handles multiple namespaces', () => {
      const token = makeJwt([
        'temporal.default.workflow.read',
        'temporal.payments.workflow.read',
      ]);
      const result = parsePermissionsFromToken(token);
      expect(result.allowedNamespaces).toEqual(['default', 'payments']);
    });
  });

  ---
  Option 2 — Built-in Mock OIDC Server (no Keycloak needed)

  The project already ships a local OIDC server (utilities/oidc-server/) that
  activates with pnpm dev:with-auth. You only need to patch it to emit
  resource_access claims in the JWT.

  Step 1 — Start everything

  Terminal 1 — Temporal server:
  pnpm temporal-server

  Terminal 2 — UI with auth mode (starts Vite + OIDC server + Temporal UI server
   automatically):
  pnpm dev:with-auth

  This brings up:
  - Vite dev server → http://localhost:3000
  - Temporal UI Server → http://localhost:8081 (API proxy)
  - OIDC Server → http://localhost:8889

  Step 2 — Patch the OIDC server to emit role claims

  The resource_access claim must be added to the access token. Edit
  utilities/oidc-server/support/configuration.ts and add a claims section to the
   provider config:

  // Inside providerConfiguration object, add:
  claims: {
    // include resource_access in the access token
    openid: ['sub', 'resource_access'],
  },
  extraTokenClaims: async (ctx, token) => {
    // Hard-code test roles here — change per test scenario
    return {
      resource_access: {
        'temporal-ui': {
          roles: [
            'temporal.default.workflow.read',
            'temporal.default.workflow.actions.signal',
            // add/remove roles to test different permission scenarios
          ],
        },
      },
    };
  },

  Step 3 — Log in and verify

  1. Open http://localhost:3000
  2. Click "Log in" — you'll be redirected to the OIDC server at
  http://localhost:8889
  3. Use any email/password (the mock accepts anything)
  4. After redirect back, open DevTools → Application → Local Storage and
  inspect the AuthUser key to see the decoded token
  5. Namespace picker should show only default; Reset/Terminate buttons should
  be disabled if those roles are absent

  Change roles without restarting — modify extraTokenClaims, log out, log back
  in.

  ---
  Option 3 — Real Keycloak via Docker

  For closer-to-production testing.

  Step 1 — Start Keycloak

  docker run -d \
    --name keycloak-temporal \
    -p 8080:8080 \
    -e KEYCLOAK_ADMIN=admin \
    -e KEYCLOAK_ADMIN_PASSWORD=admin \
    quay.io/keycloak/keycloak:24.0 start-dev

  Step 2 — Configure Keycloak (one-time setup)

  Access the admin console at http://localhost:8080 (admin / admin).

  1. Create realm: "temporal"
  2. Create client: "temporal-ui" (OpenID Connect, confidential)
     - Valid redirect URIs: http://localhost:8081/auth/sso/callback
     - Web origins: http://localhost:3000
  3. Create client roles following temporal.<namespace>.<permission> convention
  4. Create a test user, assign roles
  5. Configure the token mapper (Client scopes → temporal-ui-dedicated → Add
  mapper → User Client Role)
     - Token claim name: resource_access.temporal-ui.roles
     - Add to access token: ON

  Step 3 — Point the Temporal UI server at Keycloak

  The UI server (Go binary) reads from a config YAML. Create a local config
  file:

  # config/with-keycloak.yaml
  temporalGrpcAddress: localhost:7233
  port: 8081
  enableUi: true
  uiAssetPath: dist

  auth:
    enabled: true
    providers:
      - label: "Keycloak"
        type: oidc
        providerUrl: http://localhost:8080/realms/temporal
        clientId: temporal-ui
        clientSecret: <your-client-secret>
        scopes:
          - openid
          - profile
          - email
          - offline_access
        callbackUrl: http://localhost:8081/auth/sso/callback

  Then start Vite pointing at this config — or just run the Temporal UI server
  binary directly:
  ./temporal-ui-server --config config/with-keycloak.yaml

  And run Vite separately:
  pnpm dev:docker  # points VITE_API at http://localhost:8080 (adjust if needed)
